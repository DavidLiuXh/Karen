# 通用规则与 few-shot

本次将生产提示词中的场景补丁整理为通用决策规则，保留现有接口、状态机和模型预算。没有改变评测协议、公开标签或 DynamicAgentGraph。

## 规则的权威位置

| 规则 | 位置 | 应用边界 |
| --- | --- | --- |
| 必要前提、缺口来源、默认与省略、唯一选择 | `intent/prompts.py` 的 `TASK_GAP_INSTRUCTION` | 清晰度、目标生成及直接回应使用同一定义；先判断必要前提可满足，再判断多解能否兼容交付 |
| 当前任务问题状态和回答关联 | 同文件 `QUESTION_STATE_INSTRUCTION` | 已提问题不是新用户要求；无效或部分回答不丢失必要缺口，过度提问可以有依据地撤回 |
| 偏好的程度、范围、并存与更新 | `prompts.py` 的 `PREFERENCE_DIRECTION_INSTRUCTION` | 回答、提取与核验共用，新增兼容值不自动替换旧值 |
| 证据对当前请求的增量贡献 | 同文件 `RELEVANCE_INSTRUCTION` | 回答与精排共用；明确探索的用途可相关，但不证明已实践或形成长期偏好 |
| 长期性、计划与实际状态、有效时间 | `context/prompts.py` 的 `FACT_SEMANTICS_INSTRUCTION` | 提取与核验共用；不同语义槽位不相互替换 |
| 查询对象、时间口径和上下文依赖 | 同文件 `QUERY` | 持续属性、具体事件、任务统计按所问对象区分；目标日期不自动成为历史筛选日期 |

用户明确要求和真实证据决定规则的具体应用。不得仅因模板字段存在、模型尚不知道答案或任务还未求解，就要求用户澄清。

来源 ID、引文、输出 schema、时区字段、问题状态枚举及数据库操作是现有技术契约，保留明确说明；它们不是场景例外。

## 示例边界

场景内容只放在明确标记的 `CLARITY_EXAMPLES`、`ROUTING_EXAMPLES`、`FACT_EXAMPLES`、`QUERY_EXAMPLES` 中。提取的 JSON 层级另由 `EXTRACTION_FORMAT_EXAMPLE` 示范。

示例包含输入、决策和简短依据，用于解释必要信息与可选信息、知识缺口与歧义、不可行前提与可行性分析、计划与实际状态等边界。不附带额外授权，也不作为本轮事实或来源。模型仍须按本轮输入及实际响应 schema 输出。

没有引入示例检索器、场景路由、可配置示例库或新模型调用。原有常住城市、搬家计划和回复语言键名在记忆 few-shot 中示范；通用事实规则要求按含义复用既有槽位，不依赖这些领域名称作分支判断。记忆 prompt_version 更新为 20，便于追踪新写入记录。

后续出现失败时，应先定位通用规则、适用边界或状态契约的问题。只有能解释关键决策差异的案例才考虑进入 few-shot，其余案例进入测试，避免让示例成为不断增长的补丁清单。

## 验证范围

原有离线行为测试继续验证状态与接口契约，不以提示词包含某句话作为语义正确的证明。

`tests/fixtures/evaluation_prompt_generalization_v1.json` 在真实运行前固定 12 条迁移案例：九条使用意图适配器验证决策与目标，三条经过记忆提取、持久化、重启、召回和直接回应。内容覆盖中文、英文、真实操作定位、可省略信息、封闭前提、任务时区、兼容偏好、计划状态和后续更新。

这些新案例没有放入生产 few-shot，但由本次开发者在规则整理后编写，属于迁移回归，不宣称独立盲测或公开数据集成绩。另选原有八条澄清契约及三条既有回归保持原判定标准。所有运行结果单独保存；不替换此前固定 66 条的 54/66 基线，也不以成功补测覆盖失败。

已完成离线测试、真实回归与独立重复，结果及保留问题见 [验证报告](PROMPT_POLICY_VERIFICATION_20261007.md)。
