# 个人微信接入

[English](WEIXIN.md)

Karen 通过腾讯 iLink 接入普通个人微信，直接使用 HTTP 协议，无须安装 OpenClaw、
开通企业微信、部署公网回调服务器或控制桌面微信。账号是否可用以及登录是否被接受，
由微信服务决定。协议依据是
[Tencent/openclaw-weixin 2.4.9](https://github.com/Tencent/openclaw-weixin/blob/24de5c9eb0dd5e595d7e2d090ed8a3f82870d42c/docs/protocol_zh_CN.md)。
当前渠道采用 POSIX 文件锁，支持 macOS/Linux。

## 启动

先按 README 安装 Karen 并配置模型、向量服务。单独扫码绑定不需要模型密钥：

```bash
uv run karen --wechat-login
```

用本人的微信扫描终端二维码，在手机上确认；如微信要求验证码，在终端输入。
登录最长等待 5 分钟，二维码最多刷新 3 次。绑定者身份来自服务端确认结果，
不会把第一个发来消息的联系人当成主人。

```bash
uv run --env-file .env karen --wechat --timezone Asia/Shanghai --observe
```

`--wechat` 将交互入口切换为微信；没有凭据时自动提示扫码。原有终端入口仍为：

```bash
uv run --env-file .env karen --observe
```

只接受绑定者的私聊。陌生联系人、群聊、机器人消息和未完成的消息不会进入模型或记忆。
同一记忆和渠道目录只允许一个进程使用。Ctrl+C 退出时会等待正常的异步记忆持久化；
重新绑定前先停止运行中的渠道。凭据过期会报告 `WEIXIN_SESSION_EXPIRED` 并停止，
执行 `--wechat-login` 后重启。重新绑定为另一位用户会被拒绝，避免混用全局个人记忆。

微信会话会持久化，重启后可继续回答澄清问题。它直接复用原有意图识别、
DynamicAgentGraph 执行、全局记忆和观测流程，没有增加一层模型路由。
时区采用启动时的 `--timezone`，未指定则读取本机时区；待澄清任务保留原有 UTC 时间锚点。
当前支持一位主人、一条有序的私聊会话；
收消息、处理任务、发结果分别运行。
相对日期按入站消息的服务端时间计算，缺失时采用本地接收时间，避免排队跨午夜后改变“明天”。

## 文件与耗时任务

通过微信的**文件消息**发送附件，再说明处理要求，也可以在同一条消息内附上文字。
每个文件最多 **10 MiB**，解密后保存在 `/tmp` 下随机创建的私有目录中，文件名不能指定
任意本机路径。文件元信息与本地路径进入正常输入流程。现有 `file.read_text` 工具支持
最多 1 MiB 的 UTF-8 文本；接入渠道本身没有新增 PDF、图片或音频理解能力。
不支持的消息类型会明确报错。

如果需要收到结果文件，请明确说明，例如：

> 整理成 HTML 报告，保存在 /tmp/report.html，并把文件通过微信发给我。

任务可以在生成文件后调用 `weixin.prepare_file@1.0.0`，校验 `/tmp` 下的文件，
保存私有快照。任务成功完成后，渠道上传快照并发给绑定者。不会因为模型回答中出现一个
路径就自动发送本机文件。文件准备完成与实际投递成功分别记录。

长回复按 UTF-8 字符边界拆分，每条最多 4 KB。执行超过 15 秒会排队发送一次进度确认，
任务继续执行。进度与输入状态提示均尽力发送；进度提示只尝试一次，正式回答准备好后
取消尚未发出的提示，提示失败不会阻塞正式回答。耗时任务不会阻塞收取新消息或发送已有结果，
后续任务按收到的顺序处理。

## 恢复规则

| 场景 | 行为 |
| --- | --- |
| 重复消息、重连重放 | 按消息 ID 去重，不重复执行 |
| 收到一批消息 | 收件箱与轮询游标在同一 SQLite 事务中提交 |
| 重启时尚未开始的任务 | 按顺序继续处理 |
| 任务已完成、结果尚未发出 | 从持久化发件箱继续发送，不重做任务 |
| 执行过程中进程中断 | 告知结果无法确认，不自动重做可能已有副作用的任务 |
| 正式文字或文件发送遇到网络错误、429、5xx | 保持原 client_id，有限退避，最多尝试 5 次 |
| 永久拒绝或重试耗尽 | 保留失败记录，收到 `/retry` 后使用新的入站上下文令牌重试投递 |
| 凭据缺失或过期 | 明确报告，重新扫码 |

微信中可以使用：

- `/status`：查看任务排队数、待发送数、发送失败数。
- `/retry`：重试失败消息的投递，**不会重新执行任务**。

断网后轮询继续使用持久化游标；发送保留原请求的 `context_token`。
文件上传引用会先持久化，发送重试不会再次上传。同一回复的文字分段和文件保持顺序，
前段永久失败时，该回复剩余部分等待重试。

不承诺严格“恰好发送一次”：协议没有明确保证重复 `client_id` 的服务端去重行为，
丢失回执可能造成重复回复，但不会重做任务。进程崩溃也无法证明某个副作用是否刚刚完成，
因此不自动重放执行中的任务。长任务回复取决于微信是否继续接受原上下文令牌，
没有假设固定的有效期或无限制的主动推送能力。执行中审批和无人请求的主动通知不属于
本次渠道范围。
发送成功要求 HTTP 成功、响应为有效 JSON 对象，且没有非零 `ret` 或 `errcode`。
与腾讯实现一致，允许成功响应省略 `ret`，包括 `{}`。这表示服务端接受，不代表用户已读。

## 数据和观测

- `~/.Karne/weixin/credentials.json`：凭据，权限 0600。
- `~/.Karne/weixin/<账号哈希>/state.sqlite3`：消息、游标、会话、投递状态和文件引用，权限 0600。
- `~/.Karne/weixin/<账号哈希>/artifacts/`：结果文件快照，目录 0700、文件 0600，用于投递恢复。
- `/tmp/karen-weixin-*`：收到的附件，目录 0700、文件 0600。
- 记忆和观测继续使用原有全局目录。

这些记录包含个人对话内容，保存在本地并限制访问权限，没有进行静态加密。
文件和渠道历史会保留，本次没有引入自动清理策略；`/tmp` 文件可能被系统清理。
凭据、上下文令牌、输入状态票据、文件密钥和 CDN 参数不会进入记忆或观测日志，
原始传输消息仅保存在私有收件箱中。HTTPS 请求不跟随重定向，只允许微信域名端点。

通过 `--observe` 启动页面后，**最近微信渠道事件**展示接收、处理、投递事件和错误码。
正常任务仍出现在最近交互列表，投递事件可以关联到任务轨迹。
模型请求、记忆证据与内部诊断保留在本地观测系统中，不附加到普通微信回复中。

## 验证

自动化测试通过模拟 HTTP 和真实意图/执行链路，覆盖扫码验证码、主人隔离、文件加解密
及限制、去重、游标事务、跨重启澄清、记忆与观测、只重试投递、上传引用持久化、
中断恢复和命令行生命周期。这不能代替真实微信账号验收。

真实绑定后逐项检查：

1. 发送短消息并确认收到回复。
2. 发起需要澄清的任务，收到问题后重启 Karen，再回答，确认延续原任务。
3. 执行超过 15 秒的任务，确认收到进度提示和最终回复。
4. 发一个 UTF-8 文件要求摘要，再要求生成并回传 HTML 文件。
5. 断网后恢复，确认结果继续投递、任务未重复执行，并查看渠道事件。
6. Ctrl+C 退出后确认终端可输入，重启后确认记忆可用。

扫码、真实消息是否被服务端接受以及 CDN 实际交付，必须由绑定者使用手机单独验收。
