# 澄清状态与任务放行

本次沿用独立意图模块的 LangGraph 清晰度节点、调用方持有的 IntentSession，以及现有 DynamicAgentGraph GoalSpec 契约。每次用户回复都重新判断完整当前任务；没有增加新的路由框架、模型配置或跨进程检查点。

## 信息缺口

提示词集中在 `src/karen/intent/prompts.py`。可信时间、用户原话及适用记忆先用于解决缺口；公共信息保留原始查证对象交给执行；可安全省略的非核心偏好不阻塞。必须由用户补充且实际影响交付的缺口才进入澄清。

缺口判断和目标生成共用 TASK_GAP_INSTRUCTION：不能把用户要求得到某个结果的任务，擅自改成解释原材料为何无法满足。用户明确要求分析可行性/矛盾时，分析本身才可交付。语义判定仍由模型完成，这条提示词不能保证所有无解问题均被识别。

要求冲突的证据必须出自当前任务用户消息，助手的提问和猜测不能成为新的用户硬性要求。原有指代、证据覆盖、格式修复及时间截止策略保留。

## 状态与接口

`IntentSession.clarification_items` 是待决状态的权威定义。每条记录包含：

- `question_id`：本请求内稳定编号，改写问题不更换编号。
- `text`、`asked_after`：问题文字与首次提出时的消息位置。
- `status`：pending、answered、withdrawn 或 not_required。
- `evidence_quote`、`answer_message_index`：核验后的用户回答/纠正原话及位置。

`IntentSession.questions` 继续向 CLI/调用者返回本轮显示的问题字符串，由台账派生，最多三个。`displayed_question_ids` 只管理展示顺序，不复制问题状态；未显示的问题仍在台账中，不能放行。定位缺失历史等更具体的问题可以优先展示。

已提出的问题不是新用户要求。若复核发现原问题过度澄清，或已有可行交付使剩余字段可省略，可标为 not_required，必须引用本任务用户原话并说明可行依据；不能假称用户回答/撤销。此状态允许引用提问前的实际要求，因为它核验的是必要性，而非用户续答。

清晰度模型在同一次调用中返回 `question_updates`，无需另加逐问题模型调用。每个 pending 编号必须恰好出现一次；部分回答不能删掉其他问题。answered/withdrawn 必须引用首次提问之后的用户原话。漏项、同一响应的重复编号、未知编号、助手话语或伪造引文进入原有一次有界内容修复；失败不修改调用方原会话。已经解决的问题可以重复确认完全相同的状态与引文，这不会重写回答位置；重新标为待决、变更状态或替换引文仍被拒绝。

继续任务的输入即使被路由为信息告知，也必须经过清晰度节点；明确取消除外。未解决问题阻止最终回应和 GoalSpec 生成。澄清返回后由调用方等待用户，模型故障不会被包装成用户需要补充的信息。

独立新请求清空旧任务台账和消息、生成新 request_id；续答保留原始请求、此前答案及首次输入的可信时间。明确取消将待决问题标为 withdrawn。GoalSpec.context 保存澄清台账供内部诊断，不要求执行结果展示这些标识与引文。

当前不会在 Karen 重启后自动恢复未完成澄清。LangGraph interrupt/checkpointer 可实现跨进程恢复，但当前没有确认该需求；为此引入持久化状态和重放副作用处理会超出本次范围。
