# 可靠性机制修正

本次保留独立意图模块、m1/m2/m3 记忆模块与 DynamicAgentGraph 执行边界，调整证据交接、澄清决策和内容失败恢复。公开评测的标签、参考答案及协议 1 评分器不变。

## 证据进入模型与交付物

完整 StoredMemory、来源、版本关系和排名数据仍保存在存储及 RecallResult。模型上下文使用单独的紧凑投影，省去排序分数，以及与摘要/来源重复的行动、结果和交付物描述；事实、来源角色、时间、作用域、有效期和版本关系仍保留。模型投影保留最新事件来源及最多两个近期用户来源；m2 摘要和长引文按字节预算缩短，显式标记 text_truncated、quote_truncated、sources_complete，并在实际入选时记录 MEMORY_CONTEXT_TRUNCATED。完整记录不修改，详情定位仍使用完整来源列表；m1 事实正文、值与版本语义不裁剪。原始详情继续通过有范围的 m3 补查取得。

m2 的来源校验限定到本次新事件为止，因此按入库 sequence 定位该摘要的新增事件来源，避免因引用过助手旧说明就把整条用户新增信息当成助手背景。精排前超出输入预算时，先裁剪助手新增内容的根候选，保留入选根的原融合顺序；精排成功后优先装入 relevant 的用户新增证据，同类保持原精排顺序。精排失败仍沿用融合顺序及既有正向证据核对，不改写已确认的降级契约。版本关系按组保留，最终上下文仍限制在 12KB。coverage.evidence_selection 记录正向候选与实际保留数量；详细取舍可从 rank/assemble 追踪中核对。

意图模块从实际入选、相关且有用户来源的记录形成 evidence_to_consider。清单不是新需求或事实授权。既有回答/目标复核必须对每个 ID 恰好报告一次 evidence_coverage：

- covered：实际交付物考虑了该证据；output_quote 必须逐字存在于回答，或目标的 objective/success_criteria/constraints 中。
- context_only：只是无需逐条复述的辅助背景；须说明如何影响本轮回应。
- not_applicable：说明本轮范围、当前要求、时间或证据限制为何排除。

仅在 supporting_facts 写下某项不算 covered。ID 缺失、重复、伪造或引文不属于交付物，进入一次有界修复；再次失败不发布草稿。相关性、背景是否适当及语义覆盖仍由模型判断，这些程序校验不等于语义正确性的证明。记录通过 intent.evidence_coverage 暴露给可观测系统。

## 澄清决策

初评明确区分 resolution_source：user、external_lookup、default_or_omit，并说明 blocking_reason。只有确实由用户解决且影响有效交付的缺口进入澄清。外部身份/资料交给执行查证；默认值和非核心省略项不阻塞。日期仍使用可信时区/请求时间，澄清链仍保留完整原始请求及用户补充。

实体识别或 known_referents 不再触发全量再判断，也不通过另一次实体知识调用将模型不知道的资料变成用户需要回答的问题。

只有具体未解决指代或有原话依据的要求冲突触发一次定向核查。ClarityReview 只返回被核查的 references、requirement_conflicts 及简短依据，不能改写已有筛选标准、重新生成实体定义或添加其他指代。初评与核查及格式修复共用原 60 秒截止时间、8192 输出上限。

对直接指定指代、冲突引文和定位范围继续核对来源。将同一歧义原句改称“明确指定”不能消解指代。明确指定的引文夹带模型说明时，先作一次格式/证据修复，不把模型引文错误转成要求用户重复确认。内部理由不再受新增的 300 字符限制，仍由阶段 token/时间预算约束。材料存在矛盾不等于交付被阻塞：分析矛盾可作为结果；只有必须满足互斥要求才询问用户修正。

## 内容失败与传输失败

记忆格式、schema、证据校验失败或输出截断，可以在原单阶段 30 秒/8192 上限内修复一次。记忆提取修复时缩小为新事件及最多三个邻近事件，并限制失败草稿大小；来源核验仍对持久化原文进行，不接受截断片段或猜测来源。核验阶段不删既有事实候选，版本变更继续原子提交。

记忆提取提示词版本 19 增加合法嵌套 JSON 示例，明确 outcome 对象与 evidence 数组的位置。两条历史失败输入分别在 JSON mode 与 function calling 下各跑两次；两种方式都是 4/4，因此未据此切换 backend，也不将这个小诊断当成端到端成绩。

内容修复耗尽后使用明确的非传输错误结束本事件派生，不再把相同输入当作临时网络故障重复整个任务。m3 原文与失败状态保留，后续独立事件继续处理，已有重启恢复机制保持。网络/限流等暂时性失败仍采用原策略。

DynamicAgentGraph 的供应商截断保持非传输重试错误，但 LLM 节点可以显式进入紧凑完整重生成。它共享原 max_node_attempts、模型调用预算、节点与运行截止时间、输入和输出 schema；不重复有副作用的工具，不提交残缺产物。node_content_repair 单独记录内容修复，便于与传输重试区分。

## 减少复核重复生成

目标/回答复核可返回 AcceptedDraft（accepted=true 及完整证据覆盖报告）或完整替代 Assessment。确认分支保留原草稿的实际文字与输入，只更新覆盖报告；它仍经过同一 ID、重复、交付引用校验，不能绕过证据核对。发现事实、范围、覆盖或澄清问题时必须返回完整替代结果，不接受局部补丁。对错误覆盖报告仍只有一次有界修复，并共用原阶段截止时间。

这样避免准确草稿在复核阶段再次大量生成相同文字。schema 使用两个明确的输出分支，没有新增用户配置或模型选择框架。外部 GoalSpec 与用户回答接口不变。语义判断仍依赖模型，程序验收不能证明每条语义判断正确。

## 原话格式恢复

模型引用删掉原文的 Markdown 加粗标记时，先尝试唯一连续原文定位。只识别有明确边界的双星号加粗，保留其余字符、数字、标点和顺序；恢复结果是原始文本的实际连续子串。代码块、非唯一匹配、改写与超过 32K 字符的恢复扫描仍拒绝；长原文中的本来就逐字匹配的引文仍按原规则接受。

提取边界将原文引文写回派生候选，再进行后续核验与持久化；不修改 m3 原文。memory.source_quote_restored 记录来源与恢复方式。它只修正引文格式，不证明用户事实或助手历史结论的客观真实性。

## 排队与节点截止时间

独立重复的复杂任务实际生成六个整理分支，但两个节点等待并发名额约 27–37 秒后，只余 23–33 秒执行，原节点时限从就绪而不是实际取得名额开始。执行库修正为首次取得所有调用资源后开始共享节点时限，首次排队仅受整轮期限约束；重试、退避与再次排队不重置期限。工具 timeout_hint、剩余运行期限和调用预算继续约束执行。节点记录累计 resource_wait_seconds，事件 node_resources_acquired 标记资源到位。
