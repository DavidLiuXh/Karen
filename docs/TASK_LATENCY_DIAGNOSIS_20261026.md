## 已实施的调整

1. Karen 默认执行策略：单节点上限从 60 增至 180 秒，执行器总运行上限仍为 600 秒。节点、工具、规划和重试受共享剩余执行预算约束，较短的工具 timeout_hint 仍有效。显式传入的 ExecutionPolicy 不被覆盖。输入理解/召回另有预算；600 秒不是整轮端到端期限。
2. 参数化核验现在同时获得来源图，以及实际准备执行的 prepared_graph/prepared_goal。参数 schema 与正式实例化共享定义，防止核验模型对照旧图时把已提升的 literal 误判为“没有绑定”。结构失败仍阻断启用。
3. 无可用已启用候选时，workflow.resolve 明确记录 no_match 原因及模板状态数量，避免只看到一个成功结束的空 span。

## 下一阶段的通用修复方案（尚未实施）

1. **区分变量与固定行为。** 真正改变运行数据的日期、路径等映射为参数；始终打开浏览器等固定步骤表达为流程适用条件。不得仅因 GoalSpec 有一个字段，就声称图可切换该行为；也不能声明多个相互重叠但不会同步生效的目录/路径参数。
2. **消除指令里的旧值。** 优先让源计划通过结构化输入传递运行数据。对于已经保存的流程，若支持指令参数化，应采用明确声明、核验来源位置的受限文本槽位，验证来源值回填等价；不允许全局字符串替换、模型任意改写节点或增加权限。这需要扩展当前“遇到指令变量一律保留候选”的规则。
3. **分清复用安全与结果质量。** 固定旧日期、对象不明确、授权不足等是硬阻断；“美观”缺少证据不能声称已验收。可以结合明确关联的用户认可或隔离渲染检查补足证据。若希望主观质量 unknown 也允许复用，需明确调整此前“所有必要标准有证据才能启用”的产品策略，不能静默降低门槛。
4. **支持候选重审与版本升级。** 算法改进后应能重新核验候选并发布新版本，保留原始来源与旧判定。目前来源去重会跳过已保存来源，不能靠改索引状态或覆盖不可变 JSON 来升级旧模板。
5. **降低生成与规划成本。** 让可重复的文档版式更多使用确定性的数据填充，减少每次重新生成长文档；继续归纳 schema/绑定错误，减少无效规划轮次。复用执行图本身只跳过理解/规划，不会自动消除 worker 的生成成本。

这些方案针对通用契约和执行机制，不添加 GitHub、日期字符串或某条评测题的专用分支。
