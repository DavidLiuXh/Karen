# 澄清初评与审查机制修复（2026-10-14）

本轮实现了冲突处置契约和文本解释/操作定位的区别。两条代词原题在最新版三轮各自
3/3 通过，独立变体 8/8 通过；2050 仍未稳定解决，不能报告三个原问题全部修复成功。

## 实现

1. 审查对每个原始冲突必须恰好保留或撤销一次。撤销记录 resolved_conflicts 包含原要求对、
   连续用户原文 evidence_quote 和具体 resolution_basis。遗漏、重复、擅加要求对、无来源引文
   触发原有有界修复；仍不合法则拒绝进入目标生成。没有新增调用节点、配置或评测 ID 分支。
2. 文本理解可以根据句法、因果和上下文给出推断；材料确实不足时直接解释歧义。
   “谁/什么”等问法不自动要求用户提供唯一答案。推断不能冒充明确指定。
   必须选定收件人等操作对象且不同候选改变执行结果时，仍保留澄清。
3. 有限条件的初评要求给出简短可核验依据，不把用户声称条件成立当成成立证据。
   已识别冲突的撤销必须说明兼容解释或说明用户只要求分析矛盾。

程序只验证处置完整性和引文存在性，无法靠这些字段证明自然语言解释逻辑正确。
该限制尤其适用于初评没有发现冲突的情况：没有待审查项时，撤销契约不会触发。

### 2050 的剩余问题

- repeat-1：初评识别两个示例没有共同的候选类别；审查保留冲突，最终询问应修正示例还是
  类别定义。公共动作匹配，但评分器坚持参考追问并认为不应质疑示例，判质量失败。
  原 failed 保留；这与基于材料的人工检查存在争议，不靠照抄参考问题消除差异。
- repeat-2：初评改用按词判断的解释，认为“does not contain a negation”可由两句中的词
  共同满足；没有产生冲突审查，后续目标生成超时。说明模型对条件作用范围仍不稳定，
  不能把这次错误仅归因于等待时间。
