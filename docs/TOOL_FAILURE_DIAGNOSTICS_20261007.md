# 搜索工具失败诊断（2026-10-07）

用户报告的一次行情分析任务在执行阶段失败。已核对本地原始运行记录：规划成功，
四个 Tavily 搜索节点并行运行，各尝试两次，共八次工具调用全部失败；后续分析及汇总节点均未开始。
原记录只有 TOOL_FAILED / Registered tool failed，没有 HTTP 状态、传输异常类别或供应商失败原因。

现有代码只会对传输故障、HTTP 429 和 5xx 等可重试错误再次尝试，但原失败记录未保留具体分支。
因此不能事后认定一定是额度耗尽、密钥失效、网络故障或特定 HTTP 状态。
调查时，先作单次接口探测，再按原四个查询、相同参数并行复查；均返回 HTTP 200，每路十条结果。
这说明搜索服务调查时可用，不证明原任务已经完成，也不能替代行情分析或买入建议的验收。

## 修正

- DynamicAgentGraph 的 ToolCallError 可携带明确的错误代码及结构化诊断，保留现有默认行为。
- Tavily 分别报告 TOOL_TRANSPORT_FAILED（异常类型）、TOOL_HTTP_ERROR（HTTP 状态）和
  TOOL_RESPONSE_INVALID。只记录显式选择的诊断字段，不复制请求头、密钥、供应商正文或异常消息。
- 对外 RunResult 仍使用 TOOL_FAILED；details 增加失败工具、原因代码及安全诊断。
  节点记录保存原因，每次 node_failed 事件通过 payload_ref 指向对应尝试的失败记录。
  诊断元信息经过执行库现有敏感值过滤。
- Karen 日常终端按原因显示连接/传输失败、授权失败、限流、服务不可用或响应无效。
  未识别状态仍回退到原诊断；详细工具标识和异常类型留在可观测记录，不把整个 details 倾倒给用户。
- 不增加供应商私有响应解析、不更换搜索服务、不改变重试次数或引入股票专用处理。
