# 多轮任务与异步执行

`karen.task.TaskManager` 管理同一进程内的任务；CLI 与个人微信使用相同的 `TaskInteraction` 命令入口。理解、澄清和记忆读取可以并发推进；实际执行继续由 DynamicAgentGraph 完成。

## 使用

交互终端采用淡紫色角色标题、青色 `❯` 输入提示和分段留白；任务事件标题按状态显示青色（排队/处理）、黄色（等待回复）、绿色（完成）、红色（失败）或灰色（取消）。正文继续渲染 Markdown。设置 `NO_COLOR` 可禁用颜色；重定向与 `TERM=dumb` 使用纯文本，`--json` 使用 JSON Lines。后台输出仍通过受保护的终端输出显示，输入历史与任务命令不变。

默认同时推进 2 项任务，可通过 `--max-concurrent-tasks N` 调整，N 必须为正整数。CLI 与 `--wechat` 均适用。最多允许 32 项排队中的输入推进，超过时明确拒绝，不静默丢弃。

- `/new 内容`：创建并选中独立任务，即使当前有待回答问题。
- `/tasks`：直接查看本地任务编号、状态和请求摘要，不调用模型。`/tasks 列表`、`/tasks list` 等价；其他参数返回用法提示，不创建执行任务。
- `/use ID`：明确选择任务，下一次成功提交的普通输入归入该任务。
- `/reply ID 内容`：明确继续指定任务，可回答澄清、追问、修改交付物或在失败后补充要求。
- `/cancel ID`：取消当前排队、运行中或等待回复的轮次；任务仍可继续，已发生的副作用不回滚。
- `/finish ID`：显式结束任务，保留记录并拒绝后续输入；执行中的轮次需先取消或等待完成。
- `/schedule 自然语言`：管理持久保存的定时规则；`/schedule list` 列表，`/schedule run ID` 手动触发，`/schedule delete ID` 删除。定时任务编号与每次执行的任务编号分别使用。
- `/help`：显示命令帮助。CLI 的 `/exit` 退出并取消未完成工作。

任务具有稳定编号。每次成功接收输入后，焦点跟随所属任务；本轮完成、失败或取消不会结束任务。当前任务的已知问答、结果与产物信息直接进入后续轮次，不依赖异步记忆重新召回。新一轮会重新评估用户要求、权限及执行图，不自动重放上轮操作。

普通输入在当前任务非待澄清时，由路由模型结合该任务问答判断继续或切换：追问和调整同一目标保留编号，新目标创建隔离任务。模型路由失败时明确提示重试或使用命令指定，不默默把输入投到另一任务。`/new` 强制隔离新任务，`/reply` 与 `/use` 明确指定归属；已明确归属的澄清回复不会被模型重路由清空原请求。执行中的任务不接收中途修改，但独立新任务可以并发提交。

尚无选中任务且存在未结束的待澄清任务时，普通输入暂存，使用 `/use ID` 投递或 `/new` 将其作为新任务，无需重复输入。当前自动关联只判断当前焦点任务；回到其他已知任务可用 `/use` 或 `/reply`，没有把所有最近对话自动附加给新任务。显式结束任务后焦点清空；已结束的待澄清任务不再阻塞新输入。

CLI 输出带任务编号。`--json` 输出 JSON Lines：`type=notice` 表示入口反馈，`type=task` 表示任务事件，其中 `task_id` 为稳定任务编号，`turn_id` 标识本次输入轮次，`state` 为本轮机器状态，执行结果位于 `result`。不同任务的完成顺序不保证与输入顺序相同。终端编辑使用异步输入和受保护的输出，后台结果不会作为用户输入读取。

## 生命周期与隔离

任务生命周期由 `closed` 表示，只有 `/finish` 显式结束。`state` 表示当前或最近一轮的状态：queued、running、waiting、completed、failed、cancelled；终端对应“本轮完成/失败/取消”。`ManagedTask.turns` 保存每次输入、接收时间、轮次 ID 与结果事件，旧轮次不会被下一轮覆盖。`RunResult.run_id` 继续标识实际执行图运行，一轮直接回答时没有执行记录。

每个任务拥有独立的 IntentSession。连续澄清沿用当前请求与时间基准；上一轮交付后的继续输入开启新请求与时间基准，保留任务问答、重置旧澄清台账。轮次有独立取消信号，同一任务不能同时推进两轮；不同任务按并发名额推进，等待回复不占名额。观测按任务编号与进程会话关联多轮追踪和执行记录，旧数据仍按 request_id 关联。

执行器允许独立执行图并行，仍受任务并发上限及 DynamicAgentGraph 节点并发限制。CLI 显式保护已知文件工具：读、写、浏览器打开与微信文件快照均按实际调用参数中的规范化路径申请租约，持续到该次执行图结束；不同路径可以并行，同路径有写入时其他运行等待。共享读取允许同时持有租约，同一文件的实际工具调用仍逐次执行。租约仅在当前进程内有效。

未声明资源保护方式的工具/检查器采用整次运行独占模式，即使标记 read_only 也不自动认定它不读取共享文件。这个保守判断基于当前注册能力，因此添加未知工具可能使所有运行暂时串行。已审查的 web.fetch 和 Tavily 远程读取显式声明独立；新工具需明确保护方式才能获得并行能力。

等待实际文件资源的时间计入既有节点及执行预算；取消等待不会释放其他任务的租约。动态申请多个文件可能形成循环等待，检测到时失败退出而非无限等待。已发出的文件/快照处理完成后才释放租约，清理可能延长取消返回时间。运行准入的保守独占等待发生在引擎启动前。

同路径的覆盖仍遵循原工具规则，例如 file.write_text 要求 overwrite=true；租约不会自动改名、回滚文件、授予覆盖权限或保证旧链接永远指向旧内容。浏览器打开仍只证明发起请求，租约不覆盖浏览器后续渲染。软链接按规范化路径处理；外部程序修改、路径在检查后被外部替换、硬链接关系和跨进程协调不在此保护范围。

任务管理者向等待澄清的任务提交回复时，通过 `Karen.advance(continue_task=True)` 明确约束为继续原任务。模型仍判断输入类型、处理方式及取消意图，但不能把已明确归属的澄清回复重新判成新任务并清空原始请求、澄清台账或时间基准；发生关系纠正时记录 `task.routing_bound`。直接调用 Karen 而未指定此参数时，保留原有的语义路由行为。

取消既发出执行器取消信号，也取消当前推进协程，并等待其退出后释放名额。已产生的文件、网络请求等副作用不会回滚，不能据取消状态断言所有外部操作均未发生。

## 微信交付与退出

接收、执行和结果交付分别运行；处理新消息不等待旧任务执行完成。每轮任务结果关联触发它的原始消息及回复 token，不借用最近收到的其他消息。收件箱在最终结果保存前保持 running；接收通知走 progress outbox，不冒充任务完成。已保存结果、附件及传输重试沿用原有事务 outbox，重试发送不会重新执行任务。

任务执行会话本身仍在内存中，暂不提供完整任务持久化、执行断点恢复或多任务重启恢复；同一进程内可以在失败后继续对话或明确重试。定时规则和最近执行状态由独立的 `ScheduledTasks` 持久保存，到期后调用同一个 `TaskManager.submit` 创建独立执行。该服务只在当前渠道运行时触发，启动时跳过离线期间的周期与过期单次规则，不恢复或重做中断执行。同一规则上一轮仍在排队、运行或等待澄清时跳过周期；手动触发不改变原定时间。详见[详细指南的定时任务说明](GUIDE_cn.md#定时任务)。保留微信原有的最近一次单会话澄清检查点；它不等于恢复全部任务，恢复后任务编号会重新分配。进程中断的运行记录按既有机制报告结果不确定，不自动重做。

CLI 的 EOF 等待已接收推进结束并交付结果；`/exit` 或取消关闭任务管理者，再关闭流程发现、记忆和观测组件。正常退出仍等待既有持久化组件完成写入。

## 接口与观测

`submit(text, session, task_id=None, received_at=None, source=None)` 返回任务；`cancel(task_id)` 取消；`events` 提供带来源的状态结果；`close()` 停止接收、取消并等待工作退出。渠道负责展示和实际交付，任务管理者不直接发送消息。

`task.state` 记录任务状态与错误码，`task.turn` 将一次推进与后续输入、召回、模型和执行 trace 关联。用户文案集中在 `message/messages.py`。任务管理者不调用模型或依赖任务数据库；定时服务单独使用 `schedule_command` 解析管理请求，在私有 SQLite 中保存规则与最近状态，并通过 `schedule.created/updated/deleted/triggered/skipped` 记录变更和触发。定时触发本身不调用解析模型。


## 执行资源接入

`ExecutionResources` 与工具注册和 Karen 实例一起装配。使用 `file_tool(definition, root=..., write=...)` 包装已审查的文件工具，使用 `independent_read(definition)` 显式声明不访问受保护文件的远程读取，并将同一个实例传入 `Karen(resources=...)`。包装保留工具权限和 schema，以每文件互斥替代这些已知工具的全局不可重入锁。直接调用包装后的 engine.run_graph 时也必须在相同资源实例的 run 上下文中执行，否则工具拒绝运行。

`execution.resources` 记录并行/保守独占准入，`execution.resource_wait` 记录实际 run_id、node_id 和等待路径。DynamicAgentGraph 无需修改。
